# تقييم فرز Jev (`scripts/jev-eval`)

أدوات سطر أوامر تقيس فرز Jev لرسائل واتساب قبل الاعتماد عليه في `#/whatsapp`: ترسل رسائل مصنّفة يدوياً إلى وظيفة
`wa-triage` المنشورة، ثم تقارن أجوبتها بالتسميات وتقترح عتبات الحكم. الصورة العامة في `docs/JEV.md`؛ الأسئلة في
`supabase/functions/_shared/jev/questions.ts`، وقواعد الحكم وعتباته في `verdict.ts` بجانبها، والوظيفة في
`supabase/functions/wa-triage/index.ts`، وجدول التذاكر في `supabase/migrations/026_wa_triage.sql`.

**لا بيانات في المستودع.** المستودع عام: ملفات الرسائل والتسميات والنتائج والتقرير والتذكرة تبقى خارجه، في مجلد نسمّيه
هنا `<eval>` (مثلاً `scratchpad\eval` للجلسة). الأداتان ترفضان أي مسار داخل المستودع، مدخلاً كان أو مخرجاً (العناصر،
الذهبية، الفضية، الأحياء، النتائج، التقرير، التذكرة، المفتاح)، إلا تحت `data/` الذي يتجاهله git. النتائج نفسها لا تحمل نص
الرسائل: بصمات وتسميات واحتمالات فقط.

| الملف | عمله |
|---|---|
| `run.mjs` | يرسل العناصر إلى الوظيفة بتذكرة تقييم، 25 عنصراً في النداء، ويحفظ كل رد كاملاً في `<out>/<qset>.jsonl`. وينشئ التذكرة (`--make-ticket`) |
| `report.mjs` | يقرأ النتائج والتسميات ويكتب `report.json` و`report.md` |
| `mock-test.mjs` | اختبار كامل بلا شبكة: خادم محلي يحاكي الوظيفة، ثم الأداتان، ثم مقارنة الأرقام بحساب يدوي |

Node 24 بلا مكتبات (`node --version`). تشغيل `run.mjs` على الوظيفة الحية نداء مدفوع (سنتات لكل ألف رسالة بسعر Jev
‎$0.042 للمليون رمز)، فيتم بموافقة المالك.

## 1. التذكرة
الوظيفة تقبل نداءات التقييم بترويسة `x-triage-ticket` بدل جلسة المدير. التذكرة رمز عشوائي في ملف محلي؛ قاعدة البيانات
تحفظ بصمته `sha256` وحدها في `wa_triage_tickets` مع سقف عناصر ووقت انتهاء، وكل نداء يخصم من السقف عدد عناصره.

1. أنشئ الرمز واطبع جملة التسجيل (الرمز نفسه لا يُطبع):
   ```
   node scripts/jev-eval/run.mjs --make-ticket --ticket-file "<eval>\jev-ticket.txt" --max-items 3000 --days 3 --note "jev eval 1"
   ```
   الناتج:
   ```sql
   insert into public.wa_triage_tickets (token_hash, note, max_items, expires_at)
   values ('<64 حرفاً سداسياً>', 'jev eval 1', 3000, now() + interval '3 days');
   ```
   إن وُجد الملف أصلاً تُطبع الجملة لرمزه الموجود ولا يُنشأ غيره.
2. نفّذ الجملة مرة واحدة في SQL Editor في Supabase (مشروع `niykzsspdehexphewlxa`).
3. الرمز يبقى في الملف: لا يُلصق في محادثة ولا رسالة commit ولا سجل. احذف الملف بعد الجولة.

**حجم السقف:** عدد العناصر × عدد `--qset` × 1.1 تقريباً، لأن الدفعة المعادة تُخصم مرة ثانية.

**رمز صنعته بغير الأداة:** البصمة `sha256` للرمز نفسه بعد قصّ المسافات وBOM، لا لبايتات الملف؛ لذلك لا يصلح `Get-FileHash`
في PowerShell (يحسب سطر النهاية وBOM فيعطي بصمة لا تطابق). ضع الرمز وحده في ملف داخل `<eval>` (سطر واحد، 16 حرفاً على
الأقل من حروف لاتينية وأرقام و`-` و`_`)، ثم شغّل عليه أمر الخطوة 1 نفسه: يطبع جملة التسجيل لبصمته ولا يغيّر الملف، ويرفض ملفاً
داخل المستودع. لا تكتب ملف التذكرة بأمر يدوي يحفظه في المجلد الحالي: الأوامر هنا تُشغَّل من جذر المستودع، و`.gitignore`
لا يغطي `*.txt`، والتذكرة مع المفتاح العام تكفي لصرف نداءات Jev على حساب المالك حتى تنتهي.

**المتابعة والإلغاء:**
```sql
select id, note, max_items, used_items, expires_at from public.wa_triage_tickets order by id desc;
update public.wa_triage_tickets set expires_at = now() where token_hash = '<البصمة>';   -- إلغاء فوري
```

## 2. المفتاح العام (anon)
الوظيفة منشورة بـ `verify_jwt: true`، فبوابة Supabase ترفض أي نداء بلا JWT قبل أن يصل إلى الوظيفة. المفتاح الذي في
`js/config.js` (`sb_publishable_…`) ليس JWT والبوابة تردّه بـ «Invalid JWT». المطلوب المفتاح القديم `anon`: لوحة Supabase ←
Project Settings ← API Keys ← Legacy API keys ← `anon` `public` (يبدأ بـ `eyJ`)، أو `get_publishable_keys` في Supabase MCP.
احفظه في ملف خارج المستودع ومرّره بـ `--anon-key-file`؛ يُرسل في `Authorization: Bearer` و`apikey`.
المفتاح عام بطبيعته، لكن الأداة ترفض ملفاً فيه `sb_secret_…` أو JWT دوره `service_role`، ولا تطبع أياً منهما.

## 3. ملفات الإدخال (JSONL، سطر لكل كائن)
- **العناصر** `items.jsonl`:
  `{"id":"g0001","text":"<نص الكتلة>","group":"<اسم المجموعة>","regex_kind":"offer","split":"dev"}`
  - `text` نص الكتلة بلا رأس (لا المرسل ولا الوقت)، كما ترسله الصفحة؛ الوظيفة تخفي الجوالات قبل Jev.
  - `regex_kind` تصنيف `classify` في `crm/js/whatsapp-parse.js`: `offer | update | document | wanted | other`.
    عناصر `document` لا تصل إلى Jev (حكمها «يحتاج نظرك» من الكود).
  - `split`: `dev` لضبط العتبات و`test` للحكم عليها. قسّم بالنص المطبّع (`normalizeForDedupe`) لا بالرسالة، وإلا تسرّب
    المنشور المكرر إلى القسمين.
- **التسميات الذهبية** `gold.jsonl` بمفاتيح أسئلة `wa-1` نفسها (دليل التسمية يبقى مع البيانات في `<eval>`):
  `{"id":"g0001","intent":"sale_offer","kind":"apartment","city":"jeddah","district":"الروضة","multiple":false,"sure":true,"note":""}`
  `district` اسم الحي القانوني، أو `other_district` (حي خارج القائمة)، أو `not_stated`.
- **الفضية (اختياري)** `silver.jsonl`: عروض معروفة (من جولة 09-25) بحقول العناصر نفسها. كل سطر فيه يُعدّ عرضاً.
  تُشغَّل وحدها إلى مجلد نتائج مستقل.

## 4. التشغيل
```
node scripts/jev-eval/run.mjs --items "<eval>\items.jsonl" --qset wa-1 --qset wa-1-ar --qset wa-1-nogroup --ticket-file "<eval>\jev-ticket.txt" --anon-key-file "<eval>\anon.jwt" --out "<eval>\results"
```
كل أمر في هذا الملف سطر واحد، فيعمل كما هو في PowerShell وcmd وBash. لا تقسمه بـ `^`: هي متابعة سطر في cmd وحدها،
وPowerShell يمرّرها وسيطاً عادياً فيرفضه `run.mjs` (`unexpected argument: ^`) ويُنفَّذ السطر التالي أمراً مستقلاً.
ابدأ بتجربة صغيرة `--limit 25`، ثم شغّل الأمر نفسه بـ `--resume` لإكمال الباقي.

| الخيار | الافتراضي | المعنى |
|---|---|---|
| `--items` | — | ملف العناصر |
| `--qset` | `wa-1` | مجموعة الأسئلة، يتكرر؛ كل واحدة تُشغَّل على العناصر كلها وتكتب ملفها |
| `--url` | الوظيفة الحية | رابط الوظيفة (https فقط، إلا localhost) |
| `--ticket-file` / `--anon-key-file` | — | الملفان من القسمين 1 و2 |
| `--out` | — | مجلد النتائج |
| `--batch` | 25 | عناصر النداء الواحد (حد الوظيفة 25) |
| `--concurrency` | 2 | نداءات متزامنة (1..8) |
| `--limit N` | — | أول N عنصراً من الملف فقط |
| `--resume` | — | يتخطى ما له نتيجة ناجحة في الملف ويرسل الباقي والفاشل |
| `--timeout-ms` | 150000 | مهلة النداء (حد Supabase للطلب 150 ث) |
| `--dry-run` | — | يفحص الملفات ويطبع الخطة بلا شبكة ولا تذكرة |

**السلوك:**
- كل نداء: `{action:"triage", qset, items:[{ref:id, text, group, regex_kind}]}` مع `x-triage-ticket`.
- النداء الفاشل (شبكة، مهلة، HTTP 408 أو 429 أو 5xx، رد ليس JSON أو غير صالح) يُعاد مرة واحدة بعد ثانيتين، أو بعد
  `Retry-After` إن أرسله الخادم (حتى 10 ث)؛ إن فشل ثانية تُسجَّل عناصره فاشلة.
- غير ذلك من 4xx لا يُعاد لأن الرد لن يتغير، ويوقف التشغيل برمز 1: 400 («مجموعة أسئلة غير معروفة»، «عنصر غير صالح»)،
  404 (رابط خاطئ أو الوظيفة غير منشورة)، 413 (نداء أكبر من اللازم: صغّر `--batch`) وغيرها. الوظيفة تتحقق من الطلب قبل أن
  تخصم من التذكرة، فعناصر النداء لم تُعالَج و`--resume` يرسلها بعد الإصلاح. والأداة لا تتبع التحويل (3xx) لأن ترويسة
  التذكرة تذهب معه: مرّر الرابط النهائي بـ `--url`.
- الوظيفة تردّ 200 حتى حين يفشل Jev، وتضع الخطأ في العنصر (`{ok:false, error}`). فإن بقي أكثر من نصف عناصر النداء التي
  تحتاج Jev (كلها عدا `document`) بلا جواب (خطأ، أو غائب من الرد، أو ok بلا نية) عُدّ النداء فاشلاً، وثلاثة نداءات فاشلة
  متتالية توقف التشغيل كي لا تُستهلك التذكرة على خادم معطّل (المهلة تُدفع أيضاً: نداء Jev لا يُلغى). وخطأ عنصر يعني أن Jev
  معطّل في الوظيفة كلها يوقف التشغيل عند أول ظهور: `auth` (مفتاح OpenRouter مرفوض)، `credits` (نفد الرصيد)، `no_route`
  (لا طريق للنموذج `AGENT_TRIAGE_MODEL`)، `bad_request` (طلب Jev نفسه مرفوض). رسالة المزوّد في أحدث صفوف `wa_triage_calls`
  (عمود `error`):
  `select created_at, items, errors, error from public.wa_triage_calls where purpose = 'eval' order by id desc limit 5;`
- 401/403 توقف فوراً برسالة تفرّق بين رفض البوابة للمفتاح العام ورفض الوظيفة للتذكرة (مجهولة، منتهية، أو بلغت سقفها).
  ردّ `skipped` (الفرز متوقف: `wa_triage_mode = off`) يوقف كذلك.
- الملف الموجود لا يُكتب فوقه: بلا `--resume` يُرفض التشغيل قبل أي نداء إن وُجد ملف أيٍّ من مجموعات `--qset`، وفي
  `--dry-run` أيضاً؛ اختر مجلداً آخر لجولة جديدة.
- رموز الخروج: 0 تم · 1 مدخلات خاطئة (ومنها رفض الوظيفة للطلب بـ 4xx أو تحويل) · 2 توقف (رفض التذكرة أو المفتاح، فرز
  متوقف، Jev معطّل في الوظيفة، فشل متتالٍ) · 3 تم مع عناصر فاشلة (أعد بـ `--resume`).

**ملف النتائج** `<out>/<qset>.jsonl`، كل سطر نوع:
- `run`: بداية التشغيل (الرابط، الدفعة، التزامن، عدد العناصر). `run_end`: الناجح، الفاشل، غير المعالَج، العناصر المرسلة
  مع الإعادات (ما خُصم من التذكرة تقريباً)، الرموز، الكلفة، و`stopped`: سبب التوقف أو null (`auth` رفض 401/403، `skipped`،
  `rejected` رفض 4xx آخر أو تحويل، `jev` خطأ يعطّل Jev في الوظيفة، `failures` ثلاثة نداءات فاشلة متتالية).
- `item`: `{id, ok, result}` حيث `result` هو `ItemResult` كما ردّته الوظيفة كاملاً (`verdict`، `reasons`، و`intent`/`kind`/
  `city`/`district` بـ `choice` و`confidence` و`probabilities`، و`multiple`)، أو `{ok:false, error}`.
- `batch`: `{ids, attempts, http, latency_ms, status, model, usage:{jev_calls, cached, errors, input_tokens, cost_usd}}`.

## 5. التقرير
```
node scripts/jev-eval/report.mjs --items "<eval>\items.jsonl" --gold "<eval>\gold.jsonl" --results "<eval>\results" --out "<eval>\report" --silver "<eval>\silver.jsonl" --silver-results "<eval>\silver-results" --districts "<eval>\districts.json"
```
يكتب `report.json` (كل الأرقام، ومعرّفات الأخطاء الضارة) و`report.md` (جداول). خيارات أخرى: `--qset` لحصر المجموعات،
`--target 0.95` الدقة المطلوبة في المسح، و`--th-send/--th-skip/--th-city/--th-multiple` إن تغيّرت عتبات `verdict.ts`.

**كيف يُقرأ** (لكل `qset`، ولكل قسم `dev` و`test` والكل):
- **Population:** «answered» ما أجاب عنه Jev. `document` لا يُسأل عنه، والأخطاء تُعدّ وحدها؛ الدقة على «answered» فقط.
- **Field accuracy:** تطابق `intent`، `kind`، `city`، `district`، و`multiple` (نعم إن P ≥ 0.5) مع الذهبي. ومعها دقة
  `multiple` واستدعاؤه عند عتبة الحكم 0.6.
- **By gold `sure`:** دقة النية في الرسائل الواضحة وحدها والغامضة وحدها.
- **District:** ثلاث فئات حسب الذهبي: له حي من القائمة (يلزم الاسم نفسه بعد التطبيع)، `not_stated`، و`other_district`
  (في الأخيرتين يصح جواب `none` أو `not_stated` من الكود). `--districts` يوحّد الأسماء البديلة.
- **Regex baseline:** دقة التصنيف القديم على العناصر نفسها (offer→sale_offer، update→status_update، wanted→wanted،
  other→not_property)، ومن أصاب منهما وحده. هذا ما يضيفه Jev فوق ما عندنا.
- **Confusion:** الصفوف النية الذهبية والأعمدة جواب Jev، مع الاستدعاء والدقة لكل نية.
- **Coverage vs accuracy:** لكل عتبة t من 0.50 إلى 0.95: نسبة ما ثقته ≥ t ودقته. هنا يظهر هل الثقة تفصل الصواب عن الخطأ.
- **Calibration:** ECE على احتمال الخيار المختار بعشر خانات، وجدول الموثوقية: الفرق السالب يعني ثقة زائدة.
- **Verdicts:** الحكم بقواعد §6 معاد حسابه. «إرسال» صحيح إن كانت النية الذهبية `sale_offer` أو `status_update`، و«استبعاد»
  صحيح إن كانت `not_property` أو `wanted` أو `rent_offer`. «automated» = (إرسال + استبعاد) ÷ الكل. «offers skipped»: عروض
  استُبعدت، وهي الخطأ الأضر. «strict» يشترط أيضاً جدة أو بلا مدينة وعقاراً واحداً. «server ≠ recomputed» يجب أن يكون
  صفراً؛ غيره يعني أن العتبات أو القواعد المنشورة غير التي في التقرير.
- **Threshold sweep:** لكل عتبة إرسال ثم استبعاد على `dev`: العدد والدقة وحدّها الأدنى (ويلسون 95 %). المقترح أعلى تغطية
  بدقة ≥ 0.95 (عند التعادل الأعلى عتبة)، ثم يُطبَّق كما هو على `test`. «none/off» = لا عتبة تبلغ الدقة: يبقى للمراجعة.
  العينة الصغيرة تعطي 100 % بحدّ أدنى منخفض، فاقرأ العمود قبل نقل العتبات إلى `verdict.ts`.
- **Silver recall:** نسبة العروض المعروفة التي عدّها Jev عرضاً أو تحديثاً، وأحكامها، وحسب `regex_kind` (`other` = عروض
  أخفاها التصنيف القديم).
- **Latency and cost:** زمن النداء p50/p95 وزمن العنصر (زمن النداء ÷ عناصره، فالوظيفة تعالجها متوازية)، الرموز والكلفة
  لكل نداء Jev ولكل عنصر.

## 6. الاختبار المحلي
```
node scripts/jev-eval/mock-test.mjs
```
بلا شبكة ولا مفاتيح: يشغّل خادماً محلياً يحاكي البوابة والوظيفة (فحص Bearer، بصمة التذكرة وسقفها، 1..25 عنصراً، أجوبة
ثابتة باحتمالات معروفة، رفض 503 مرة واحدة)، ثم `run.mjs` على عشرة عناصر مصطنعة وثلاثة فضية، ثم `report.mjs`، ويقارن
كل رقم بحساب يدوي مكتوب في تعليقاته. يغطي أيضاً الاستئناف، والتوقف عند 401 وسقف التذكرة و`skipped`، ورفض المفاتيح الخاطئة
والمسارات داخل المستودع، وأن الرمز والمفتاح ونص الرسائل لا تظهر في أي مخرج. `JEV_EVAL_KEEP=1` يبقي المجلد المؤقت لرؤية
تقرير نموذجي.
