# ربط النطاق باللوحة الجديدة (GitHub Pages)

الوضع الحالي: اللوحة والـ CRM يعملان على `https://mohammedalseari-design.github.io/mulaem-dash/` ولا يعتمدان على
GoDaddy في شيء (الكود على GitHub، البيانات على Supabase، الصور في مخزن Supabase). الرابط القديم `dash.mulaem.sa`
ما زال يشير إلى استضافة GoDaddy القديمة (PHP + MySQL).

## القرار المطلوب أولاً

- **الخيار أ — إبقاء `dash.mulaem.sa` وتحويله إلى اللوحة الجديدة:** الموظفون لا يغيّرون عاداتهم. لحظة تغيير DNS
  يتوقف النظام القديم نهائياً (وهذا مقصود، لأن كل شيء انتقل).
- **الخيار ب — نطاق فرعي جديد مثل `app.mulaem.sa`:** يبقى القديم يعمل مؤقتاً بجانب الجديد. مناسب إن أردت فترة
  تشغيل متوازٍ أسبوعاً أو أسبوعين.

الخطوات واحدة في الحالتين، يتغير الاسم فقط. الأمثلة أدناه بـ `dash.mulaem.sa`.

## الخطوات

1. **في GoDaddy (إدارة DNS لنطاق mulaem.sa):** أضف أو عدّل سجل CNAME:
   - النوع: `CNAME` — الاسم: `dash` — القيمة: `mohammedalseari-design.github.io` — TTL: 600.
   - إن كان هناك سجل `A` أو `CNAME` قديم لنفس الاسم `dash` يشير إلى استضافة GoDaddy، احذفه أولاً (اسم واحد لا يحمل
     سجلين متعارضين).
2. **في المستودع:** أضف ملفاً باسم `CNAME` (بلا امتداد) في جذر المستودع يحتوي سطراً واحداً: `dash.mulaem.sa`،
   وارفعه. (يمكن لـ Claude Code فعل ذلك بجملة واحدة: "Add a CNAME file at the repo root containing dash.mulaem.sa,
   commit and push".)
3. **في GitHub:** Settings ← Pages ← Custom domain: اكتب `dash.mulaem.sa` واضغط Save. انتظر حتى يظهر "DNS check
   successful" (قد يأخذ من دقائق إلى ساعة بحسب انتشار DNS)، ثم فعّل **Enforce HTTPS**.
4. **التحقق:** افتح `https://dash.mulaem.sa/` ثم `https://dash.mulaem.sa/crm/`. الرابط القديم على github.io سيحوّل
   تلقائياً إلى النطاق الجديد.

## ملاحظات مهمة

- الموقع في مسار جذري بعد الربط (`https://dash.mulaem.sa/` بدل `/mulaem-dash/`). الكود يستخدم مسارات نسبية فقط،
  فلا يحتاج تعديلاً.
- لا تُلغِ استضافة GoDaddy قبل التأكد من عمل النطاق الجديد يومين على الأقل. بعدها الإلغاء آمن؛ لم يبقَ عليها شيء.
- الموقع العام `mulaem.sa` (الصفحة التسويقية) موضوع مستقل ولا يتأثر بهذه الخطوة.
